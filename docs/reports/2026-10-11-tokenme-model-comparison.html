Published · not a head-to-head run

Evidence beyond this small test

Qwen’s model card reports 42.2% on DeepSWE 1.1 and 61.7% on SWE-bench Pro, using a Claude Code harness. Public reporting of OpenAI’s launch result gives Sol 75.2% on DeepSWE 1.1 at high effort.

Different evaluators, harnesses, sampling and reasoning budgets prevent treating these as a controlled head-to-head. The Sol live test here uses low effort, not the published high setting.

NVIDIA’s exact Gemma NVFP4 card reports 79.8% LiveCodeBench, versus 80.5% BF16 in its own run.

That small quantization gap applies only to NVIDIA’s evaluation. It does not guarantee equivalent Qwen NVFP4 quality or faster hosted service. No separate Qwen NVFP4 evaluation was verified.

What to expect in Cat Code

Gemma: simple, bounded work

Summaries, extraction, classification and short answers are reasonable candidates to evaluate. Its MoE design has about 25.2B total and 3.8B active parameters. Active parameter count alone does not determine service speed or answer quality.

Qwen: test as a coding helper

Its published agentic-coding evidence makes it a candidate for inexpensive focused work. Compare regular and NVFP4 on your own tasks; a smaller numeric format does not guarantee faster requests or cheaper billing.

Sol: retain the main-agent baseline

This is the existing Cat Code model and tool environment. Neither a compatible chat endpoint nor eight correct answers demonstrates drop-in compatibility with Cat Code’s tools, permissions, context assembly and multi-turn workflow.

These are candidate roles, not a validated model-routing policy. No Cat Code provider configuration was changed.

Sources and method

  • OpenAI: GPT‑6.1 Sol model and pricing
  • Qwen3.8 official model card and evaluations
  • NVIDIA: exact Gemma NVFP4 model and evaluations
  • DeepInfra Gemma reference pricing
  • DeepInfra Qwen current promotion and list prices
  • TokenMe public site; no price found
  • Sol launch-result reporting, including DeepSWE

Each model received the same synthetic task and JSON-only instruction, without tools or private repository content. Fresh requests ran serially; model order rotated by task. Provider-side prefix caching was not disabled: Gemma reported some cached input. TokenMe output was capped at 2,048 tokens, while Sol used the existing Codex adapter’s default output budget. Temperature was left at each provider’s default. Those differences and only three timing repeats limit inference. Grading did not forgive Markdown wrappers, extra keys, or incorrect answers. API transport errors stop the experiment instead of silently retrying. Credential inventory was read without live pool initialization, token refresh or account rotation. Credentials are excluded from this report.
