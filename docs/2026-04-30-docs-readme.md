# Docs

Folder-level index. Files are mostly dated and historical (investigation → plan → outcome); treat the dated filename as a timestamp, not a sign the doc is current. Where a folder has one canonical/live doc, it's called out below.

- `docs/vision/` — long-term product vision and goals. Canonical: `docs/vision/2026-04-30-GOAL_PLAN.md`.
- `docs/migration/` — the Claude→Cat Code migration program. Canonical: `docs/migration/STATUS.md` (current phase state), `docs/migration/PROGRAM-PLAN.md` (phase plan), `docs/migration/README.md` (program overview).
- `docs/maps/` — subsystem maps for source navigation. Canonical: `docs/maps/WORKSPACE_MAP.md` (index of all maps).
- `docs/prompts/` — prompt/instruction-surface design docs. Canonical: `docs/prompts/2026-04-30-prompt-surfaces.md`.
- `docs/agent/` — Agent Mode design history (v1 → v2 → v2.4 iterations, feedback, gaps).
- `docs/codex/` — Codex/OpenAI backend integration: bugs, cache/perf investigations, account-leasing and usage-reset design.
- `docs/design/` — UI/app design specs. `docs/design/dedicated-app/` has its own index: `docs/design/dedicated-app/handoff-index.md`.
- `docs/plans/` and `docs/superpowers/plans/` — dated implementation plans for specific features/fixes; largely historical once shipped.
- `docs/reports/` — investigation and bug reports, often tied to a specific debugging session.
- `docs/research/` — deeper standalone research/deep-dive writeups.
- `docs/reviews/` — point-in-time code/design reviews.
- `docs/reference/` — small standing reference docs (e.g. extraction maps, flag audits).
- `docs/superpowers/specs/` — feature specs paired with `docs/superpowers/plans/`.

Loose root docs: `docs/abort-semantics.md`, `docs/ptclove-bridge.md`.

For active phase status, see `docs/migration/STATUS.md`.
