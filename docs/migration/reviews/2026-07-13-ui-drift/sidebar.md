## Findings (High → Low)

[High] StatusChip's dynamic Tailwind class silently no-ops, breaking tone-color coding for every non-live row: `className={\`shrink-0 font-mono text-[10px] uppercase tracking-wide ${toneTextClass(tone)}/75\`}` (`Sidebar.tsx:543`) concatenates the `/75` opacity modifier onto a function-call result. Tailwind v4's scanner only ever sees the literal source text; it finds `text-tone-good`/`text-tone-warn`/`text-tone-danger`/`text-accent` as bare literals inside `toneTextClass`'s `switch` (`Sidebar.tsx:574-583`) but never the composed string `text-tone-warn/75` etc., because that string is only ever assembled at runtime. Confirmed empirically: the built stylesheet (`app/renderer/dist/assets/index-CQ6qWk2G.css`) contains `.text-tone-good`, `.text-tone-warn`, `.text-tone-danger` but **zero** occurrences of any `\/75`-suffixed variant of those classes. Effect: the rendered `<span>` carries an unrecognized one-word class (`"text-tone-warn/75"`, no space) that matches no CSS rule at all — not just "not dimmed," the whole tone-color is dropped and the chip falls back to inherited text color. TabBar's own identical `toneTextClass` (`TabBar.tsx:316,360`) is unaffected because it never appends a suffix outside the interpolation. Fix: replace with a static per-tone map whose *values* are the complete literal strings, e.g. a `toneTextClassDimmed(tone)` switch returning `'text-tone-warn/75'`, `'text-accent/75'`, `'text-tone-danger/75'` as whole literals (mirrors the existing `AGENT_DOT_CLASS` static-map idiom, `AgentsPage.tsx:58`).

[Med] Session-row title loses the prototype's 3-state color grammar and uses the wrong "active" shade. Prototype (`Sidebar.jsx:266`): idle `#c4c4c8`, hover/menu-open `#f4f4f5`, active `#fce7f3` (near-white pink). Ours (`Sidebar.tsx:400-407`) only distinguishes 2 states — `text-text-muted` (`#a1a1aa`) idle, `text-accent-soft` (`#f9a8d4`) active — with **no hover-color change at all** (only the row's background/border react to hover, `Sidebar.tsx:372-375`), and the active shade (`#f9a8d4`) is a materially more saturated pink than the prototype's near-white `#fce7f3`. `#f9a8d4` is correctly reused for the NAV items (prototype's own active-nav color, `Sidebar.jsx:182,303`) but that's a different element with a different literal in the prototype. Fix: add a hover variant (e.g. `group-hover:text-text-primary`) and reconsider the active-row token — `text-text-primary` (`#f4f4f5`) is closer to the prototype's `#fce7f3` than `accent-soft` is.

[Med] Hover-brightening across several rail controls resolves one step dimmer than the prototype because no token sits between `text-muted` (`#a1a1aa`) and `text-primary` (`#f4f4f5`). Prototype hover targets: rail-nav icon hover `#d4d4d8` (`Sidebar.jsx:186`), expanded-nav icon hover `#d4d4d8` (`Sidebar.jsx:306`), search-input idle text `#d4d4d8` (`Sidebar.jsx:208`, not even a hover — it's the resting color). Ours: `NavItemRail`/`NavItemExpanded` hover both go to `hover:text-text-muted` (`Sidebar.tsx:522`, `:471`) → `#a1a1aa`, the same shade already used for idle NAV icons elsewhere, so the "hover brighten" reads as a much smaller jump than the prototype's. Fix: either add a `~#d4d4d8` token for these hover/rest targets or hover straight to `text-text-primary`.

[Med] Sidebar's fixed rail is `z-40` (`Sidebar.tsx:129`), not the prototype's dedicated `zIndex: 50` (`Sidebar.jsx:131`). `z-40` is shared with at least one full-screen overlay in this codebase — `CommandPalette.tsx:103` (`fixed inset-0 z-40`) — so if the command palette opens while the rail is hovered/pinned open, stacking falls back to DOM order instead of the prototype's guaranteed sidebar-on-top. Fix: bump the rail to `z-50` (and audit whatever currently assumes `z-50` is exclusive, e.g. `PlanPanel.tsx:144`).

[Low] Search input color/border don't match: prototype text `#d4d4d8`, border `rgba(255,255,255,0.07)` (`Sidebar.jsx:207-208`). Ours: `text-text-muted` (`#a1a1aa`, dimmer) and `border-white/10` (`0.10`, heavier) (`Sidebar.tsx:182`). Fix: a brighter text color (see above) and `border-white/[0.07]`.

[Low] Five "chrome" micro-elements use `text-text-subtle` (`#71717a`) where the prototype paints a distinctly darker gray, `#52525b`: pin-icon idle (`Sidebar.jsx:160` vs `Sidebar.tsx:160-161`), search-icon stroke (`Sidebar.jsx:205` vs `Sidebar.tsx:173-174`), group chevron (`Sidebar.jsx:221` vs `Sidebar.tsx:319-321`), workspace-group label (`Sidebar.jsx:224` vs `Sidebar.tsx:327`), row recency timestamp (`Sidebar.jsx:268` vs `Sidebar.tsx:409`). Note this is *not* true of the NAV icons — those correctly resolve to `#71717a` on both sides (`Sidebar.jsx:182,303` vs `Sidebar.tsx:519,469` `text-text-subtle`). The theme has no token for `#52525b`; `text-subtle` is doing double duty for two different prototype grays. Fix: add a `text-chrome-dim` (~`#52525b`) token for these five spots.

[Low] Rail width/box-shadow transition: prototype `transition: 'width 0.18s cubic-bezier(0.2,0,0,1), box-shadow 0.18s'` (`Sidebar.jsx:135`). Ours: `transition-[width,box-shadow] duration-200 ease-out` (`Sidebar.tsx:128`) — 200ms vs 180ms, and Tailwind's stock `ease-out` instead of the custom curve. Fix: `duration-[180ms] ease-[cubic-bezier(0.2,0,0,1)]`.

[Low] "Cat Code" wordmark letter-spacing: prototype `-0.01em` (`Sidebar.jsx:150`). Ours: `tracking-tight` (`Sidebar.tsx:144`), Tailwind's `-0.025em` — roughly 2.5× tighter than intended. Fix: `tracking-[-0.01em]`.
