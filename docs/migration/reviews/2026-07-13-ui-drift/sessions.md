## Findings (High → Low)

[Med] "Blue" workspace/cross-project chrome renders pink instead of an available blue token: SessionsPage's "All workspaces" toggle (`SessionsPage.tsx:169-187`, `border-tone-info/40 bg-tone-info/10 text-tone-info`), `GroupHeader`'s non-current workspace name+folder icon (`SessionsPage.tsx:440-449`), and the "other workspace" cross-project chip (comment at `SessionsPage.tsx:366-370`) all fall back to `tone-info`, which `theme.css:28` aliases straight to the pink accent. The code comment claims "the shell palette has no distinct blue," but `theme.css:67` defines `--color-source-project: #60a5fa` — the exact hex the prototype uses for this chrome (`SessionsPage.jsx:535-543` toggle `rgba(96,165,250,.3)`/`#93c5fd`, `:362-367` GroupHeader `#60a5fa`/`#93c5fd`, `:312` cross-project badge `#60a5fa`) — and it's already wired as a Tailwind utility elsewhere (Settings source badges). Fix: use `border-source-project/40 bg-source-project/10 text-source-project` (or a new blue tone) at these three call sites instead of `tone-info`/`default`.

[Med] Floating popovers use the rail-chrome token instead of the popover token: the sort-dropdown panel (`SessionsPage.tsx:145`) and the `SessionActionsMenu` panel (`SessionActionsMenu.tsx:59`) both use `bg-shell-chrome border-shell-seam` (`#070709`, `theme.css:37` — the TabBar/Sidebar rail color). The prototype's own literal popover background for both is `#141417` (`SessionsPage.jsx:512`; `SessionActions.jsx:34` `SA.menuBg`, used at `:191`) — much closer to the purpose-built `--color-surface-raised: #111113` (`theme.css:46`, doc-commented as exactly "a toast/popover [that] sits one step ABOVE the app body"). Fix: swap `bg-shell-chrome` → `bg-surface-raised` on both popovers.

[Med] `SessionActionsMenu` row hover has no accent tint: the enabled-row hover in `MenuRow` (`SessionActionsMenu.tsx:104-114`) is plain `hover:bg-white/[0.05] hover:text-text-primary` — no color shift at all for non-danger rows. The prototype's non-danger row hover is pink-tinted end-to-end (`SessionActions.jsx:125-130`: bg `rgba(244,114,182,.14)`, border `rgba(244,114,182,.3)`, text `#fce7f3`, icon `#f9a8d4`). Fix: `hover:bg-accent/10 hover:border-accent/25 hover:text-accent-soft` (same composition `toneClasses('accent').hoverTint` already produces for `Chip`, `tone.ts:59`).

[Med] Missing "HISTORY" section-label text in `SessionActionsMenu`: the prototype renders an uppercase small-caps label above the branch/rewind/metadata group (`SessionActions.jsx:144-146` `SectionLabel`, used at `:169`); ours (`SessionActionsMenu.tsx:41-76`) renders only a 1px divider between sections — no label text at all for `primary`/`history`/`transfer`. Fix: add a label row (e.g. `text-[9.5px] font-bold uppercase tracking-wide text-text-subtle/50 px-2.5 pt-1.5`) before the `history` group at minimum, matching the prototype's one labeled section.

[Low] Session-row "emphasis pink" uses the base accent instead of the lighter token `theme.css` reserves for it: the New-session button label (`SessionsPage.tsx:102-108`, `text-accent`), the sort-dropdown active item (`SessionsPage.tsx:154-159`), the active tag-filter tab (`SessionsPage.tsx:198-204`), and the row `#tag` label (`SessionsPage.tsx:388-390`) all render `text-accent` (`#f472b6`). [Low] Empty state is missing its icon: the prototype shows a 28×28 message-bubble glyph at `opacity: 0.28` above the headline (`SessionsPage.jsx:583`); ours (`SessionsPage.tsx:462-489` `EmptyState`) renders only headline + subtext.
