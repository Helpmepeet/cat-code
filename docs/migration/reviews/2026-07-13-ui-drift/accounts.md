## Findings (High → Low)

[SEVERITY Med] Headroom-bar reset time dropped everywhere: prototype's `HeadroomBar` renders `↺{reset}` next to every 5h/weekly bar (`Pages.jsx:365`) and the header hero widget shows `↺ resets {w.reset}` under each stat (`Pages.jsx:545`) — both backed by the real `usageResetAt` field (`app/shared/protocol.ts:1104`, `codexAccountPool.ts:1223`). Our `HeadroomBar` (`AccountsPage.tsx:204-224`) and `ActiveHeadroom` (`AccountsPage.tsx:671-713`) never render any reset text at all — the field is available (already used elsewhere on the page, `AccountsPage.tsx:660-662` for the capped non-usable branch) but silently unused in both bar components. `PARITY-LEDGER.md:999`, `:1013`, `:1014` all claim this reset text is "✅ built" and "REAL" — the ledger is wrong on this point (see Doc-drift notes). Fix: add a muted `↺{formatResetLabel(usageResetAt)}` span after the `%` in `HeadroomBar` for the "5h" row (the weekly reset has no backing field — correctly stays omitted, see Deferred).

[SEVERITY Med] Active/hero-row accent glow entirely missing: prototype's hero `Row` gets a two-layer `boxShadow: '0 0 0 1px rgba(244,114,182,0.06), 0 8px 24px -12px rgba(244,114,182,0.25)'` (`Pages.jsx:405`) plus a glowing dot `boxShadow: '0 0 8px rgba(244,114,182,0.6)'` (`Pages.jsx:410`), and the header hero widget's dot gets `boxShadow: '0 0 6px rgba(244,114,182,0.6)'` (`Pages.jsx:528`). None of the three shadows exist in our `PoolRow` (`AccountsPage.tsx:617-667`, only `border-accent/25 bg-accent/5`, no shadow class) or `ActiveHeadroom` (`AccountsPage.tsx:673-682`, plain `bg-accent` dot). `PARITY-LEDGER.md:1008` explicitly credits "elevated border/glow" as built. Fix: add a `shadow-[0_8px_24px_-12px_rgba(244,114,182,0.25)]` (or equivalent static arbitrary-value utility — not interpolated) to the hero row and a small `shadow-[0_0_8px_rgba(244,114,182,0.6)]` to the two accent dots.

[SEVERITY Med] `DangerBtn` color/contrast diverges from source: prototype's `alBtn.danger` is `background:'#ef4444', color:'#fff'` (`AccountLifecycle.jsx:31`). Ours (`AccountsPage.tsx:186-202`) is `bg-tone-danger` (`#f87171`, `theme.css:27`) with `text-app-bg` (`#09090b`) — a lighter/different red family AND inverted text contrast (dark text on a light-red pill vs white text on a saturated red pill in the prototype). Fix: either add a dedicated darker `--tone-danger-strong:#ef4444` token for buttons only, or at minimum switch `DangerBtn`'s text to `text-tone-default`/white to match the prototype's white-on-red delete button.

[SEVERITY Med] Status-dot color ignores "active" once unhealthy: prototype's dot color is `pressured ? amber : (isDflt ? pink : sc.color)` (`Pages.jsx:409`) — the active/default account's dot is **pink regardless of status** (dead/capped/quarantined) except the pressured override. Our `statusDotTone` (`AccountsPage.tsx:88-95`) only returns `'accent'` when `account.isDefault && account.status === 'healthy'`; a dead or capped default account falls through to `'danger'`/`'warn'` instead of staying accent-tinted. Real-world effect: if your active pool account goes dead or gets capped, its dot no longer reads as "this is the one you're using," diverging from the prototype's always-pink-if-active rule. Fix: move the `isDefault` check ahead of the status branches (mirroring the prototype's precedence), keeping the `usageLimitReached` pressured-amber override first.

[SEVERITY Med] `TouchAllDialog` running state collapses to one generic line instead of per-account rows: prototype renders one row per known vault account immediately, each with its own spinner, using the already-available `accounts` prop (`AccountLifecycle.jsx:211-221`). Ours (`AccountsPage.tsx:496-503`) shows a single `"Refreshing…"` line with one shared spinner while `running`, only rendering the per-account result list after the real `account.touchAll` result arrives. The known vault-account list is available client-side (`selectAccountRows` filtered by `hasVaultProfile`) so a per-row skeleton could be shown immediately, closer to source. `PARITY-LEDGER.md:1117` credits "per-row spinner while running" as built, which the source does not do. Fix: render one row per vault account (from the snapshot) with a spinner from the start, flip each row to OK/LOCKED/FAILED when the batched result lands.

[SEVERITY Low] `GhostBtn` border half as visible: prototype's `alBtn.ghost` border is `1px solid rgba(255,255,255,0.12)` (`AccountLifecycle.jsx:30`). Ours uses `border-shell-seam` (`AccountsPage.tsx:179`), which is `rgba(255,255,255,0.06)` (`theme.css:38`) — exactly half the opacity, making Cancel/ghost buttons read fainter than source. Fix: use a heavier border utility (`border-white/12` or a dedicated button-border token) instead of reusing the ambient chrome-hairline token.

[SEVERITY Low] Hero vs non-hero row padding/radius not differentiated: prototype gives the hero row `padding:'14px 16px', borderRadius:12` vs the roster row `padding:'11px 14px', borderRadius:10` (`Pages.jsx:402`). Ours applies the same `px-4 py-3` (16px/12px) to both hero and non-hero rows (`AccountsPage.tsx:619`), and non-hero radius is `rounded-lg` (8px) vs the prototype's 10px. Fix: give the non-hero branch `px-3.5 py-2.5 rounded-[10px]` and keep hero at `px-4 py-3.5 rounded-xl`.

[SEVERITY Low] Redundant reset text on capped rows: the engine-authored `availabilityLabel` for a capped account already reads `"Limit reached (resets in 2h 14m)"` (`codexAccountPool.ts:1538`) and is shown as the row's status line (`AccountsPage.tsx:645`); the same row's `flex-1` branch separately renders `"Resets {formatResetLabel(...)}"` again (`AccountsPage.tsx:660-662`) right next to it — the reset time is stated twice in different phrasing in the same row. Fix: drop the second `Resets …` string for the capped case (keep it only for the currently-unhandled non-capped non-usable states, if any).

[SEVERITY Low] Non-hero row background noticeably fainter than source: prototype's roster row background is a flat `rgba(255,255,255,0.018)` (`Pages.jsx:404`). Ours uses `bg-shell-hover/20` (`AccountsPage.tsx:622`) where `--color-shell-hover` is already `rgba(255,255,255,0.045)` (`theme.css:39`) — the `/20` modifier multiplies that alpha down to ≈0.009, about half of source. Fix: use `bg-white/[0.018]` (static arbitrary value, not interpolated) or a dedicated row-background token instead of scaling the ambient hover token.
