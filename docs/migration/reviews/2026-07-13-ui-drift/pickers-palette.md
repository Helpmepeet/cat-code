## Scoreboard — H:0 M:2 L:5

## Findings (High → Low)

[Med] Overlay background/border use the wrong design token — CommandPalette and SlashCommandPicker paint their floating popover shell with `shell-chrome`/`shell-seam` (the TabBar/sidebar-rail chrome tokens, `#070709` / `rgba(255,255,255,0.06)` per `app/renderer/src/theme.css:37-38`), not `surface-raised` (`#111113`, `app/renderer/src/theme.css:46` — its own doc comment says this is *for* "a toast/popover"). The prototype's exact literal is `#111113` for CommandPalette (`CommandPalette.jsx:195`) and `#0d0d10` for SlashCommandPicker (`SlashCommandPicker.jsx:41`, closer to `surface-raised` than to `shell-chrome` either way), and the sibling `MentionPicker.tsx:75` (same P4-1 kit) correctly uses `bg-surface-raised border-white/10` and lands an exact hex match. CommandPalette (`CommandPalette.tsx:107`) and SlashCommandPicker (`SlashCommandPicker.tsx:103`) instead render visibly darker/fainter-bordered than the prototype and than their own sibling component. Fix: `bg-shell-chrome` → `bg-surface-raised`, `border-shell-seam` → `border-white/10` on both containers (matches the token theme.css already defines for this exact purpose, and matches `MentionPicker.tsx:75`).

[Med] No token models the prototype's darkest "barely-visible" gray tier (`#3f3f46`), so every element that used it renders one step brighter/more visible than intended via `text-subtle` (`#71717a`, `theme.css:50`). Instances: CommandPalette `GroupHeader` (`CommandPalette.tsx:254-260` vs `CommandPalette.jsx:88-94` `GrpLabel` `color:'#3f3f46'`), CommandPalette footer hint labels (`CommandPalette.tsx:164-177` vs `CommandPalette.jsx:210-217`, label spans `color:'#3f3f46'`), SlashCommandPicker's "Commands" label and match-count badge (`SlashCommandPicker.tsx:112-121` vs `SlashCommandPicker.jsx:71,80-83`, both `color:'#3f3f46'`), and MentionPicker's close-× / sub-line / empty-state text (`MentionPicker.tsx:104,143,114` vs `Surfaces.jsx:1065,1081` `color:'#52525b'`). Net effect: the whole picker family's "quietest" chrome text sits noticeably closer in brightness to primary/muted text than the prototype's hierarchy intends. Fix: either add a fourth text tier (e.g. `--color-text-faint: #3f3f46`) or accept `text-subtle` as the floor and flag the delta as a deliberate simplification — currently it's neither, it's an unflagged one-tier compression.

[Low] CommandPalette container radius/shadow: prototype `borderRadius:16` + `boxShadow:'0 32px 80px rgba(0,0,0,0.75)'` (`CommandPalette.jsx:195`) vs ours `rounded-xl` (12px) + `shadow-[0_28px_70px_rgba(0,0,0,0.7)]` (`CommandPalette.tsx:107`). Fix: `rounded-xl` → `rounded-2xl`.

[Low] SlashCommandPicker container radius: prototype `borderRadius:12` (`SlashCommandPicker.jsx:43`) vs ours `rounded-lg` (8px, `SlashCommandPicker.tsx:103`). Fix: `rounded-lg` → `rounded-xl`.

[Low] CommandPalette footer legend `<kbd>` chips are missing the border the prototype gives them: `border:'1px solid rgba(255,255,255,0.08)'` (`CommandPalette.jsx:210-217`) vs ours `rounded bg-shell-hover px-1.5 py-0.5 ...` with no border class (`CommandPalette.tsx:171-173`) — SlashCommandPicker's equivalent footer kbd DOES carry a border (`SlashCommandPicker.tsx:171`), so this is an inconsistency within our own picker family, not just vs. the prototype. Fix: add `border border-shell-seam` to the footer `<kbd>` in `CommandPalette.tsx:171-173` (and to the header ESC kbd at `:124-126` only if intended — prototype's header ESC kbd has no border either, so leave that one alone).

[Low] MentionPicker default anchor position drifts from the prototype default: prototype's caller-side default is `{ left: 16, bottom: 'calc(100% + 6px)' }` (`Chat.jsx:1343`) vs our component-level default `'absolute left-0 bottom-[calc(100%+8px)]'` (`MentionPicker.tsx:55`). `App.tsx:2237-2243` (the only live mount) passes no `className` override, so this default is what actually renders. Fix: `left-0` → `left-4`, `+8px` → `+6px` if pixel parity matters here.

[Low] MentionPicker active-tab label color: prototype's active tab text is a light pink `#fce7f3` (`Surfaces.jsx:1061`) vs ours `text-accent` (`#f472b6`, same shade as the active border, `MentionPicker.tsx:91`). Low impact: `App.tsx` never passes `tabs` to the live mount (flat single-source list, tabs omitted per ledger), so this only affects the shared primitive's unused tab-chrome path.

## Doc-drift notes

- `PARITY-LEDGER.md:618` and `:685` both wave at "tokens not hex" for the CommandPalette/SlashCommandPicker container as if it were a settled stylistic substitution, but neither checks the actual resolved hex against the prototype literal. Doing that math (this review) shows the components picked the *wrong* token category — `shell-chrome` (persistent app-shell chrome) instead of `surface-raised` (floating popovers, which `theme.css:41-47`'s own comment says is exactly for this) — and that the sibling `MentionPicker` (built later, same P4-1 kit) already uses the correct one. Worth a follow-up note in the ledger rather than leaving it read as "fine, just tokenized."
- Several `PARITY-LEDGER.md` rows for this area (`:624` ESC kbd, `:630` GroupHeader, `:688` "Commands" label, `:690` match-count badge) are marked "✅ built... same visual grammar" without a hex check; per this review's Med finding, their text color is a real (if small) step brighter than the prototype's `#3f3f46` because no equivalent token exists. Not severe enough to flip the ✅, but the "same visual grammar" claim overstates pixel parity.
