## Findings (High → Low)

[High] MetadataInspector is unreachable — the component is fully built (drawer, all sections, `selectMessageMetadata`/`selectMessageRefs`) but nothing in the renderer ever mounts it: `grep -rl MetadataInspector app/` matches only `MetadataInspector.tsx`, `MetadataInspector.test.tsx`, and `messageMetadata.ts` (its own data layer) — never `App.tsx` or `SessionsPage.tsx`. `SessionsPage.tsx` imports `SessionActionsMenu`/`resolveSessionActions` (lines 22-29) but `git diff HEAD -- app/renderer/src/SessionsPage.tsx` shows those imports are the *entire* diff — no `<SessionActionsMenu>` JSX, no anchor/open-menu state, no `onAction` handler exists in the file, so the "Inspect metadata…" verb (`sessionActions.ts:136-141`, enabled when `isActiveOpen`) has no menu to fire from and no handler to open the drawer even if it did. Fix: wire a `⋯` trigger on `SessionRow` (`SessionsPage.tsx:344-394`) that opens `SessionActionsMenu`, and an `onAction` case for `'metadata'` that mounts `<MetadataInspector>` with the active session's `SessionMetadataView` + `RawMessageSessionLog`.

[High] Colored-pill treatment is missing everywhere in `MetadataInspector.tsx` — the prototype's `MIPill` (`MetadataInspector.jsx:48-50`: `background: color+'18'`, `border: 1px solid color+'33'`, `borderRadius:5`, `padding:'1px 7px'`, mono font) is a filled badge; every value it's used for in our build instead renders as bare tone-colored text with no background/border/radius at all:
  - Thread-goal Status (`MetadataInspector.jsx:115` `MIPill` ↔ `MetadataInspector.tsx:238-241` `GoalStatus`: `<span className={t.text}>{status}</span>` — no `softBg`/`softBorder` despite `tone.ts` exposing exactly those fields).
  - Tag (`MetadataInspector.jsx:94` `MIPill` ↔ `MetadataInspector.tsx:96-102`: `<span className="font-mono text-accent">#{session.tag}</span>`).
  - Message "Kind" role label (`MetadataInspector.tsx:228-236` `RolePill`, `:218-220` `MessagePickRow` role label) — same bare-text pattern (no direct prototype counterpart since this row is new, but it repeats the same missing-chip bug).
  This is a systemic single-cause bug (nobody added the fill/border classes), and the fix already exists in the same app: reuse `Chip` (`app/renderer/src/Chip.tsx`) or add `${t.softBg} ${t.softBorder} rounded-[5px] border px-1.5 py-0.5 font-mono` to these spans.

[Med] `RemoteSettingsPage.tsx:321-327` Connect button is a **solid** fill (`bg-accent … text-app-bg`) — the prototype's Connect button (`RemoteSettings.jsx:221`: `border 1px solid rgba(244,114,182,.4)`, `background rgba(244,114,182,.12)`, `color #f9a8d4`) and every other accent CTA in this same prototype file (`BridgePanel`'s inactive Start-bridge button, `RemoteSettings.jsx:90-96`) use a ghost/tinted style, never a solid fill. Fix: `border border-accent/40 bg-accent/12 text-accent-soft` instead of `bg-accent text-app-bg`.

[Med] Bridge toggle button text color ignores the theme's own "soft" token — `RemoteSettings.jsx:94`: `color: active ? '#fca5a5' : '#f9a8d4'` (a lighter shade than the border/bg tone, for text-contrast). `RemoteSettingsPage.tsx:180-191` uses the SAME full-strength tone for text as for border/bg (`text-accent` inactive, `text-tone-danger` active), even though `theme.css:13` defines `--accent-soft: #f9a8d4` specifically for "text sits one step brighter than the accent" cases. Fix: `text-accent-soft` when inactive; `text-red-300` (Tailwind default `#fca5a5`, exact match) or `text-[#fca5a5]` when active.

[Med] `MetadataInspector.tsx` never closes on Escape — prototype (`MetadataInspector.jsx:53-57`) attaches a `window` keydown listener calling `onClose` on `Escape`, and advertises it via the close button's `title="Close (Esc)"` (`:80`). Our drawer (`MetadataInspector.tsx:56-195`, close button `:78-87`) has neither the listener nor the title. `SessionActionsMenu.tsx:33-39` — built in the same uncommitted batch — implements the identical pattern, so it's a direct copy. Fix: add the same `useEffect` + `title="Close (Esc)"`.

[Low] RemoteSettings.jsx's own "good"-tone literal is `#34d399` (emerald-400) throughout this file — `statusPill('Publishing', '#34d399')` (`:73`), `FilterCard tone="#34d399"` for "Allowed: skills" (`:159`), direct-connect `status.color: '#34d399'` (`:182`) — while our shared `--tone-good` token (`theme.css:25`) resolves to `#4ade80` (green-400, sourced from other prototype surfaces per that same theme.css comment). Perceptually close but a measurable per-file hex mismatch; both the "Enabled" `Chip` (`RemoteSettingsPage.tsx:161`) and the "Allowed: skills" `FilterCard` (`:215`) inherit it. No token surgery needed — flagging for awareness only.

[Low] `MetadataInspector.tsx`'s drawer panel (`:63-67`) doesn't use the app's own `.animate-toast-in` slide-in class (`theme.css:114-117`) even though the prototype's drawer animates in (`MetadataInspector.jsx:71`: `animation: 'toast-in 0.18s ease both'`) and `PARITY-LEDGER.md:1281` itself suggests reusing the shared keyframe. Fix: add `animate-toast-in` to the drawer `className`.

[Low] Minor copy nits vs the prototype: Tag empty-state renders `—` (`MetadataInspector.tsx:97-101`) where the prototype shows the word `none` (`MetadataInspector.jsx:94`); Thread-goal Budget's unbounded branch (`MetadataInspector.tsx:114-116`) renders `"{tokens}k tokens · unbounded"` where the prototype shows the bare word `unbounded` (`MetadataInspector.jsx:116`, no token count). Neither is wrong, both add information the prototype omits — flagged as content drift, not a functional bug.

[Low] Header chrome nits in `MetadataInspector.tsx:75-87`: the `read-only` badge has no background tint (prototype `:79` has `background: rgba(255,255,255,0.04)`) and looser letter-spacing (`tracking-wide` ≈0.025em vs prototype's `letterSpacing:'0.05em'`); the close button is `26x26` with a text-color-only hover (`:80-87`) vs the prototype's `30x30` button with both a background AND color hover transition (`:80-84`). Fix: add `bg-white/[0.04]` to the badge and `hover:bg-white/[0.06]` to the close button; bump to `h-[30px] w-[30px]` to match.
