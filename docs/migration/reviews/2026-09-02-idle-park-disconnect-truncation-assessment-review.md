## Claims that survived challenge

- The full-ring composition is real. The authorized aggregate rerun found the same 41 at-cap caches, 318,938 `stream_event` frames at a 763.2 B mean, and 8,663 finished messages at a 3,791.9 B mean. That supports roughly 211 finished messages per full ring and about 2,200 finished messages per 8 MiB without deltas.
- Ordinary quit does skip parked registry rows: `markLiveCleanSync` marks only `shutdown === null` ([`registry.ts:882-899`](../../../app/host/registry.ts#L882-L899)), and the next read normalizes persisted `parked` to `crashed` ([`registry.ts:1244-1251`](../../../app/host/registry.ts#L1244-L1251)). The descriptor then loses its parked bit and the visual mapper prints `crashed` ([`host.ts:888-918`](../../../app/host/host.ts#L888-L918), [`sessionStatusVisual.ts:74-84`](../../../app/renderer/src/sessionStatusVisual.ts#L74-L84)). Recommendation 1 is sound.
- Both reported load-earlier completeness holes follow from current source: a live session with no restored `history` returns `complete: true` ([`sidecarServer.ts:4467-4477`](../../../app/sidecar/sidecarServer.ts#L4467-L4477)), while a reloaded resumed session retains the attach-time per-connection anchor ([`sidecarServer.ts:1119-1123`](../../../app/sidecar/sidecarServer.ts#L1119-L1123)).
- The displayed boundary intentionally omits the retained count, so the assessment correctly notes that `retainedMessageCount` currently has no user-visible consumer.
