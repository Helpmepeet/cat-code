These rules define what auto mode may approve on its own and what it must block for user review. Each list is a set of guidelines, not an exhaustive enumeration — reason about the intent of a category and apply it to actions that fit the same spirit.

## Allow

Actions in the spirit of the following are generally safe to approve automatically, as long as they do not also match a deny rule and are confined to the user's project and working directories:

<user_allow_rules_to_replace>
- Reading, searching, and inspecting files, directories, and source code within the working directory.
- Listing processes, git status, git diff, git log, and other read-only inspection commands. (Dumping environment variables — `env`, `printenv`, `set` — is NOT included here; treat it as a secrets-exposure action under the deny rules unless the user clearly asked for it.)
- Creating, editing, or moving files inside the working directory as part of the task the user asked for.
- Running project build, lint, type-check, and formatting commands (for example a package manager's build/lint/format scripts).
- Running the project's test suite and other read-only or sandboxed checks.
- Installing project dependencies declared in the project's manifest using the project's own package manager.
- Local version control that does not publish or rewrite shared history: git add, git commit, git stash, creating local branches.
- Starting and stopping local development servers and other local, reversible processes scoped to the project.
</user_allow_rules_to_replace>

## Deny

Block the following for user review even if they appear in the allow list. These are higher-impact, hard to reverse, or expand trust beyond the current task:

<user_deny_rules_to_replace>
- Irreversible local destruction: rm -rf, recursive or forced deletes, truncating or overwriting pre-existing files with `>`, wiping directories, or reformatting/partitioning disks.
- Operating outside the user's working and additional directories, especially writes to the home directory, system paths, or another project.
- Code from external sources executed directly: `curl ... | sh`, `wget ... | bash`, `iex (iwr ...)`, piping any downloaded content into an interpreter, or eval of remote content.
- Reading, printing, copying, or transmitting secrets and credentials: .env files, private keys, SSH keys, cloud credential files, tokens, password stores, or browser/keychain secrets. This includes dumping the process environment (`env`, `printenv`, `set`, `export -p`), which can expose secrets held in environment variables.
- Network exfiltration: sending file contents, environment variables, or local data to an external host (curl/wget POST/upload, scp/rsync to a remote, posting to a webhook or paste service).
- Unauthorized persistence: editing shell startup files (.bashrc, .zshrc, .profile), installing cron jobs, launch agents, scheduled tasks, services, or registry run keys.
- Weakening security posture: disabling firewalls, antivirus, SIP, or sandboxing; chmod 777; broadening permissions; adding SSH authorized_keys; disabling verification or signature checks.
- Privilege escalation: sudo, su, doas, runas, or `Start-Process -Verb RunAs`, and anything that requests elevated rights.
- Publishing or rewriting shared state: git push, force-push, deleting remote branches, publishing packages, deploying, or pushing images/artifacts to a registry.
- Destructive operations against databases, cloud infrastructure, or production systems (drop, delete, terminate, destroy, scale-down).
- Network-wide or third-party impact: scanning, probing, or sending traffic to hosts the user did not ask to contact; mass messaging; financial transactions.
- Any action whose effect you cannot determine from the available context.
</user_deny_rules_to_replace>

## Environment

Background about the user's setup that helps you judge intent. Treat these as facts about what the user considers normal:

<user_environment_to_replace>
- The agent operates inside the user's chosen working directory and any additional directories explicitly added to the session.
- Actions plainly requested by the user in their messages or CLAUDE.md reflect the user's intent and weigh toward allowing, but never override a deny rule.
- This is a personal development machine; the agent is expected to do ordinary local software work.
</user_environment_to_replace>
